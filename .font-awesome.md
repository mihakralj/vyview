# Font Awesome Configuration

Detected by the Font Awesome agent tools. Commit this file so the whole team benefits.

## Integration

- **Method:** SVG Sprites + Bare SVGs via Font Awesome CLI (`fa`)
- **Version:** 7.3.1
- **License:** Pro
- **Families:** sharp, duotone, sharp-duotone, classic

## Defaults

- **Style:** light
- **Family:** sharp

## Import Pattern

- Icons are fetched from the Font Awesome Pro API via the `fa` CLI (`fa icons --version 7.3.1 --name <icon> --svg-format html`) using the **Sharp Light** (`fa-sharp fa-light`, `sharp` family + `light` style) variant, or downloaded from a self-hosted Pro Kit (`fa kit download --kit-token <TOKEN> --unzip --output <dir> web`).
- Embedded in the server-rendered `<svg class="icon-sprite" aria-hidden="true">` `<symbol>` sprite in `internal/demo/templates/shell.html` and referenced via `<svg class="nav-icon"><use href="#fa-<icon-name>"></use></svg>`.

## Conventions

- **Default Icon Variant:** **Sharp Light** (`sharp` family, `light` style) across navigation, status indicators, and UI chrome, pairing with the flat, square geometric UI and **IBM Plex Sans** / **IBM Plex Mono** typography.
- **Zero external runtime dependencies:** All SVGs are embedded into the Go binary at build time (`go:embed`); no CDN or runtime Font Awesome JS is loaded on the router.
- **Dual-pack leak protection:** Per `docs/DESIGN-BRIEF-ANALYSIS.md` §4.2, private builds (`-tags fapro`) use Font Awesome Pro 7.3.1 Sharp Light SVGs while public/upstream builds fall back to Font Awesome Free 7.3.1 SVGs with identical `<symbol id="fa-...">` IDs.
